## Definition of a completed cycle

1. Fill in the candidate path, symbol, source SHA, owner and intended user-visible behavior. Change the row status to investigating. For a clone, choose one authoritative owner and list every consumer to migrate.
2. Prove reachability or retirement across the relevant runtime entry points. Include main/preload channels, dynamic feature imports, worker/Edge entry points, CLI commands, mocks and sibling repos. Exercise synthetic data in an isolated backend. Capture the same result on the baseline and candidate revisions.
3. Make a single reversible change on a cleanup branch. For larger migrations, first add equivalence tests and a compatibility export or adapter, switch consumers, then retire the old path in a separate commit. Keep recovery, database migrations and live data outside that change.
4. Run the gates for that row. For startup/IPC changes, test a packaged Electron build on a compatible host; a Chromium login smoke covers renderer behavior only. For finance/sync changes, compare writes, amounts and duplicate-operation counts across retry and reconnect. A new failure, lost permission check, extra write or changed result blocks retirement.
5. Record before/after evidence, test names, commit and actual net production LOC. Count tests, archived scripts, install bytes and emitted JS separately. Mark removed, unified, retained with consumer, or pending with the missing proof. Revert the specific change on a regression. Continue until every row has a disposition and each newly discovered candidate has been reviewed.

## Why the estimates differ

The published 12.8% scenario uses 345,145 lines and includes archival, test helpers, mock generation and cross-app extraction. The local 6.34% scenario uses 225,938 production lines and models non-overlapping within-runtime clone substitutions, including unverified semantic matches. The 414-line sample was a small manually reviewed subset. These figures overlap and depend on different assumptions. Use actual merged diffs and passing behavior gates to measure progress. A fully dispositioned backlog is a stronger completion criterion than reaching a percentage.
