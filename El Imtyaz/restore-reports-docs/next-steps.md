## Priority 2 — UI/Logic Separation in Feature Pages

**Why:** Top remaining large files violate Single Responsibility Principle. Business logic embedded in React components is hard to test and reuse.

**Scope:**
- `configuration-tab.tsx` (914 LOC) — extract config logic into `useConfiguration()` hook.
- `dashboard-page.tsx` (914 LOC) — extract dashboard data orchestration into `useDashboardData()` hook.
- `onboarding-wizard.tsx` (877 LOC) — extract wizard state machine into `useOnboardingWizard()` hook.
- `batch-registration-modal.tsx` (793 LOC) — extract form validation + submission into `useBatchRegistration()` hook.

**Approach:**
1. Write characterization tests capturing current behavior.
2. Extract business logic into custom hooks (`features/<feature>/hooks/`).
3. Extract pure helpers into `features/<feature>/utils/`.
4. Component becomes thin render layer that calls hooks and renders UI.
5. Verify all existing tests still pass.

**Estimated effort:** 1-2 iterations
**Risk:** Medium — touches user-facing components. Characterization tests mitigate regression risk.

## Longer-Term Roadmap

### Supabase Adapter Completion
Port the remaining 38 repositories from mock to Supabase. Each port is self-contained:
1. Implement Supabase adapter for the repository interface.
2. Replace mock in `getSupabaseRepositories()`.
3. Test against deployed Supabase project.
4. Verify mock fallback still works for development.

**Priority:** High for production deployment. SQL schema + Edge Functions + RLS policies ALL ready — only TypeScript adapter layer missing.

### Real-Time Sync Conflict Resolution
Current sync uses last-write-wins, which may lose data. Add `updated_at` column to every table + conflict resolution logic (e.g., CRDTs or operational transforms).

**Priority:** Medium — only matters when multiple clients edit same data simultaneously.

### Per-Entity Sync Push Routing
Replace single `sync_queue` table with per-table upserts. Each entity type routes to its own Supabase table.

**Priority:** Medium — current single-table approach works but doesn't scale.

### Real AI API Calls
Replace mock LLM adapter with real Groq + OpenRouter via Edge Function proxy. Edge Function exists (`ai-proxy`), just needs real API keys configured via Settings → Configuration → IA.

**Priority:** Low for core functionality (AI features are optional enhancements).

### BON + Devis Sheet Importers
Write per-record parsers for non-tabular sheets. Requires understanding the per-client layout format.

**Priority:** Low — ETAT sheet (primary client roster) works correctly.

### Mobile Parity Verification

**Priority:** Low for desktop-focused work.

### Playwright E2E Tests

**Priority:** Low — unit + component + integration tests provide good coverage. E2E adds confidence but is not blocking.

## Process Improvements (Going Forward)

1. **Adopt conventional commits** repo-wide: `feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `chore:`. Reject `cv`/`kk`/`mid`/`go` style messages in pre-commit hooks.
2. **Enforce max-commit-size policy** — warn at >500 lines, block at >2,000 unless explicitly flagged.
3. **Run full test suite on every commit** (CI). A commit that breaks tests should not reach `main`.
4. **Commit tests separately from features** when feasible.
5. **Never commit build artifacts.** `.gitignore` them.
6. **Document iteration boundaries** with tagged releases (`v0.1.0-iter18`).
