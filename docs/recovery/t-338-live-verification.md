## What the diff CAUGHT and fixed in the SQL truth itself

1. **The call-list cap** — the SQL emitted all 196 chronic families; the derivation's call list is the TOP 10 exposures (`.slice(0, 10)`). Fixed with `ORDER BY outstanding DESC LIMIT 10`.
2. **Double-attribution of transport money** — a family with riders on two routes (chabat + chabet) had its installments counted in BOTH routes by the SQL JOIN; the derivation attributes first-seen. Fixed with `DISTINCT ON (parent_id) … ORDER BY parent_id, student_id` (the deterministic mirror of the TS first-match rule; the runner pins the students order by `id`).
3. *(Earlier, corpus-side)* **The BOUMRDES/BOUMRDS transcription trap** — the desktop's own doc comment says the live typo is "BOUMRDS" but its code, fixtures, and generated corpus all use **"BOUMRDES"**; the first Android mirror attempt followed the comment and the corpus diff failed — the exact defect class the corpus exists to catch. The Android table now mirrors the CODE verbatim (and a follow-up should fix the desktop doc comment).
