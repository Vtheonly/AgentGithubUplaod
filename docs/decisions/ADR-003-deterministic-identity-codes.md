# ADR-003 — Identity codes are deterministic (FNV-1a), never random or sequential

## Status

Accepted (2026-08-29)

## Context

Parents (`PAR-YYYY-XXXX`), students (`ELV-…`) and activation codes identify entities across three platforms and the Excel import. The canonical rule (legacy spec §7.1) requires deterministic derivation so that re-imports and re-syncs converge on the same row.

## Problem

Six-plus generation paths still use `Math.random()`, `gen_random_bytes()`, per-device counters or `count+1` sequencing: the desktop mock repository, the `approve-signup-request` EF, `batch_register_family` SQL RPC, Android `createStudent`/`batchRegister`, and the Android sync dispatcher's fallback generators. Random codes break idempotent upserts (duplicate parents), sequential codes collide across devices and reuse dead rows' codes (DRIFT-001 family).

## Decision

All identity codes are generated by the canonical deterministic functions: desktop `deterministicParentCode` / `deterministicActivationCode` (`src/core/format/id.ts`), Android `IdentityCodes.kt` equivalents, and the `upsert_*_from_import` RPCs' deterministic generation. Random/sequential generators are deleted, not merely bypassed.

## Alternatives

- Server-generated codes via sequences — rejected for parents/students: breaks offline-first creation and Excel re-import convergence.
- Keeping random generators for "demo mode" — rejected: mock mode must exercise the same rules it claims to test (the mock/production divergence already hides idempotency bugs).

## Consequences

- Same input ⇒ same code, on every platform, online or offline.
- Collisions from genuinely identical identity inputs are handled by the upsert semantics, not by the code generator.
- Activation-code entropy is a separate, open question (UNKNOWN-008) — determinism of the *client-side canonical function* does not preclude choosing a stronger server-side issuance format.

## Affected Components

Desktop `src/core/format/id.ts`, mock repositories, `approve-signup-request` EF; Android `IdentityCodes.kt`, `LocalRepositories.kt`, `SyncQueueDispatcher.kt`; SQL `batch_register_family`.

## Verification

Unit tests: same identity input produces identical codes across desktop TS and Android Kotlin; re-running any import/sync twice creates no duplicate rows; dead random exports removed (grep clean).
